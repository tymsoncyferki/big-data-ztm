\section{Testing}

This document presents the functional tests of the data acquisition and preprocessing modules
as well as the quality tests of the data transformations. All tests were run on the full Docker
deployment (NiFi, Kafka, HDFS, Spark) with live data acquisition turned on. Screenshots and logs
are in the Appendix (Section~\ref{sec:appendix}).

\subsection{Functional Tests}

The functional tests check that the acquisition and preprocessing modules work as intended. We test
if NiFi receives GPS, weather and air quality data from the simulator and publishes it to Kafka,
if raw snapshots and GTFS archives are saved in HDFS, and if Spark cleans the raw data and builds
the enriched datasets.

\subsection{Quality Tests}

The quality tests check that the transformations give correct data. We run unit tests on synthetic
data with known results, check if GPS trips match the GTFS timetable and compare raw and cleaned
data.

\subsection{Data Quality Statistics}\label{sec:q3}

Table~\ref{tab:q3} compares raw and cleaned records for one full day (21 November 2026).

\hline
GPS & 7001611 & 3362210 & 52\% & none \\
\hline
Weather & 46080 & 46080 & 0\% & around 500 values -32000 \\
\hline
Air quality & 2226240 & 2223360 & 0.13\% & none \\
\hline
\end{tabular}
\caption{Raw and cleaned data on 21 November 2026 (Q3).}
\label{tab:q3}
\end{table}

It can be seen that most of the removed GPS records are duplicates. The simulator asks for data every 10 s,
but it turned out that the source updates positions only about every 20 s, so the same position comes twice.
The weather API puts -32000 in place of missing values - these values are replaced with NULL when the ML dataset is built.
All sources have data in about 152 of 165 hours, the missing hours are the time
when acquisition was stopped, not a pipeline failure.

\subsection{Summary}

All functional tests passed. Data from the three live sources goes through NiFi to HDFS and Kafka
without changes, GTFS is downloaded every day and Spark cleans and enriches the data on schedule.
The quality tests confirm that the transformations are correct (29 of 29 unit tests) and that all
GPS trips match the timetable. The found problems (duplicates and -32000 values) are handled in
the pipeline.
